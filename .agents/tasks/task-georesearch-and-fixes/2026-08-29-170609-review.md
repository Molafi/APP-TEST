# Reminder-failure fixes, Firestore batch chunking, and a GeoResearch soil-estimate feature

This change set does two things. It closes three documented defects — a notification scheduler that swallowed failures so a rejected reminder still showed as enabled, hardcoded-English reminder bodies, and Firestore batch deletes that blew past the 500-op `WriteBatch` limit on large collections — and it adds a new GeoResearch feature that produces an estimated soil profile (depth, salinity/salt, sodium, N/P/K nutrients, pH, organic matter, contaminants, structure/geometry, suitable plants) from location context and an optional site photo. The georesearch module deliberately mirrors the existing diagnosis architecture (tolerant JSON parse, local + Firestore repositories, a `StateNotifier` flow, a demo-gateway canned path) and is wired in as a new home tab. The whole feature is framed as an educational estimate that repeatedly tells the user to commission a professional soil-lab test.

Watch for: the home-tab reshuffle (georesearch inserted at index 2, pushing weather to 3 and profile to 4) — all navigation goes through the `HomeTab` symbolic constants, so no stale index references remain (confirmed). `ReminderController.toggle` is now dead code after the UI switched to `update` (confirmed, low risk). French/Spanish only received 2 of the ~44 new localization keys, so georesearch UI labels fall back to English for those locales — this matches the pre-existing partial-translation state of those files (confirmed, not a regression).

**Verdict**: APPROVED

## High-level view

The reminder fix moves the failure boundary to the right place: `scheduleReminder` no longer catches-and-logs, so a rejected OS schedule now propagates to `ReminderController._schedule`, which reverts the reminder to `enabled=false` and re-persists so the stored/UI state matches what was actually scheduled. Localized bodies are threaded in from the presentation layer via an optional `localizedBody` argument, keeping the `StateNotifier` free of any `BuildContext` hack; `_defaultBody` survives as an English fallback.

The Firestore fix is a single reusable `FirestoreBatch` helper (a pure `chunk` splitter plus a chunked `deleteAll`) applied uniformly to all five delete-all sites, making large-thread and large-collection deletes safe against the 500-op cap.

GeoResearch reuses the diagnosis playbook rather than inventing a new one. `SoilReport` parses tolerantly (fenced-JSON stripping, balanced-brace fallback, null/empty tolerance, safe enum defaults) and every field is qualitative — the prompt forbids fabricated precise numbers and demands a lab-test disclaimer in every note. The demo gateway disambiguates soil requests from diagnosis requests by a stable marker token embedded in the instruction, so demo mode returns a valid canned `SoilReport` without breaking the existing diagnosis demo path.

Integration adds GeoResearch as home tab index 2. Because every call site references `HomeTab.*` constants rather than raw integers, shifting weather and profile down by one is self-consistent.

The user's request is met end to end: soil depth, sodium and salt, nutrients, substances, and geometry-from-image are all represented in the schema, the prompt, the demo output, and the report UI, and the "for building also" angle is addressed by safety notes that explicitly warn against using these estimates for construction/foundation decisions and point to a geotechnical survey.

### Reminder scheduling: moving the failure boundary

The previous `scheduleReminder` wrapped `zonedSchedule` in a try/catch that only called `debugPrint`, so a genuine OS rejection (revoked permission, exact-alarm limit) was indistinguishable from success — the reminder stayed `enabled` and persisted as if a notification were pending. The fix removes that swallow so the error reaches `_schedule`, which reverts the offending reminder to `enabled=false` and re-persists. The three regression tests exercise the real seam: a `FakeNotificationService(throwOnSchedule: true)` drives the failure, one asserts the in-memory state reverts to disabled, and another reconstructs a fresh `ReminderController` from the same cache to prove the disabled state was persisted, not just held in memory — they would fail if the revert were removed.

One asymmetry: `add()` appends the reminder and persists it as enabled *before* calling `_schedule`, so on failure there are two writes (enabled, then reverted to disabled). The end state is consistent and the intermediate persisted-enabled write is not observable across a restart.

`toggle` still exists and calls `update` without a `localizedBody`, but nothing calls `toggle` anymore — the reminders screen now calls `update(r.copyWith(enabled: !r.enabled), localizedBody: ...)` directly. The localized-body path is covered for the toggle action; `toggle` is simply orphaned.

### Localized reminder bodies

Resolution order in `_schedule` is `note ?? localizedBody ?? _defaultBody(type)` — a user's custom note wins, then the localized default, then the English fallback. `_defaultBody` is retained for any future non-UI caller that threads in no localized string.

### Firestore batch chunking

`FirestoreBatch.chunk` is a pure splitter (unit-tested at boundaries 0/10/500/501/1250 and a custom size), and `deleteAll` commits one `WriteBatch` per chunk. The conversations case is the one that motivated the fix: a thread with >500 messages. Its conversation doc is appended to the message-ref list, so it lands in the final chunk after its messages — the correct deletion ordering.

### SoilReport parsing robustness

`SoilReport.parse` mirrors the diagnosis parser: strip a leading ```` ```json ```` fence, attempt a fast `jsonDecode`, then fall back to extracting the first balanced `{...}` block when the model wraps JSON in prose. Scalars trim to null, lists drop empty/blank entries, nutrients and substances drop nameless entries, and unknown enum strings default conservatively (`confidence`→low, `imageQuality`→unusable, `SoilLevel`→low); `isSoilRelated` defaults to true when absent. The parse tests cover clean JSON, fenced+prose, missing-optionals, non-JSON (throws `FormatException`), unknown-enum defaulting, and the nameless-entry drop — a reverted tolerant parse would fail several of these.

### Demo gateway request disambiguation

Soil and diagnosis requests both arrive in `jsonMode`, so the demo gateway routes on `AiPrompts.soilResearchMarker` (`PLANTSENSE_SOIL_RESEARCH_V1`), a stable token embedded at the top of the soil instruction, matched in either the user text or system prompt. The service always appends `soilResearchInstruction()` (which carries the marker), so routing is deterministic. Tests confirm both directions: a soil request yields a populated, parseable `SoilReport`, and a plain "diagnose this plant" jsonMode request still returns diagnosis JSON (`isPlantRelated` present, `isSoilRelated` absent). The coupling is guarded by a "do not translate/reword without updating the demo gateway" comment on the marker.

### Responsible framing of estimates

The prompt requires the model to use only provided context, reason about *likely regional* characteristics without site-specific certainty, use qualitative low/medium/high levels instead of invented ppm/pH numbers, keep confidence conservative, and put a lab-test caveat in every note plus the disclaimer. The demo output follows suit — every note says "estimate" and "lab test needed," confidence is `low`, and safety notes explicitly warn against using the estimates for construction, drainage, or foundation decisions and recommend a geotechnical survey. That answers the "for building also" part of the request without posing as a substitute for a real survey.

### Home-tab integration

GeoResearch is inserted at `IndexedStack`/`NavigationBar` index 2, shifting weather to 3 and profile to 4. The reshuffle risk is a stale hardcoded index. Every navigation site references `HomeTab.chat` / `HomeTab.weather` constants (home app bar's weather chip, diagnosis/plant-detail/georesearch "go to chat" jumps, the back-to-chat pop handler), and `NavigationBar.selectedIndex`/`onDestinationSelected` bind to the provider value directly — no raw integer index assignments exist.
